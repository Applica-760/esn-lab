# リモートの階層を確認してディレクトリを取得するTask

[research-hub Issue #2](https://github.com/Applica-760/research-slide/issues/2) の独立Task。
SSHによる階層一覧の取得と、確認・承認を経てローカルへコピーするAPIを実装している。
同じアプリからディレクトリの選択・取得確認画面も配信する。

## 接続先と保存先はcfg.yamlで指定する

- `ssh`: ホスト・ユーザー・秘密鍵のパス・ポート・接続維持設定。秘密鍵の内容は書かない。
- `remote_root`: リモートの絶対パス。初期値は確認済みのesn-labのClone先。
- `initial_path`: 最初に開く階層と転送時の相対階層の基準。`remote_root` からの相対パスで、初期値は `outputs`。取得対象はこの配下に限る。
- `local_destination`: ローカル保存先。ローカルのesn-labリポジトリルートからの相対パスで、初期値は `outputs/downloads/genkai/`。転送開始時に作成する。親への遡行や保存先のリンクは拒否する。
- `output_dir`・`port`: 既存Taskの設定保存先と、ローカルAPIのポート。初期ポートは8001。

## 起動と画面操作

リポジトリルートから実行する。

```sh
uv run -m projects.tasks.cli remote_data_browser
```

既定のURLは `http://127.0.0.1:8001/`。ポートを変更した場合はcfg.yamlの値を使う。

1. 「開く」「親へ戻る」で階層を移動する。閲覧範囲は `initial_path` 配下。
2. ラジオボタンで取得するディレクトリを1つ選ぶ。現在のディレクトリ自体も選択できる。選択だけでは確認や転送を開始しない。
3. 独立した「Enter — 取得内容を確認」ボタンを押す。
4. 保存先・ファイル数・除外対象を確認する。同名ファイルがある場合は衝突一覧と警告を表示する。「選択に戻る」で取得せず戻れる。
5. 「取得する」、衝突がある場合は「上書きする」で転送を開始する。

転送中は画面内の操作を無効化し、完了・失敗を表示する。進捗率と転送開始後の取消は設けない。
通信が切れた場合は転送が続いている可能性があるため、状態を確認してからEnterで取得内容を確認し直す。
リンク・特殊ファイルは取得対象外と表示し、選択・階層移動はできない。

## 階層取得API

| GET API | 内容 |
| --- | --- |
| `/api/config` | リモートルート・初期階層・ローカル保存先を返す。SSHの認証設定は返さない。 |
| `/api/directories` | 初期階層の直下を取得する。 |
| `/api/directories?path=outputs/experiments` | 指定した相対パスの直下を取得する。 |

一覧は `path`・`parent`・`entries` を返す。各項目は `name`・`path`・`type` を持ち、typeは `directory`・`file`・`symlink`・`other`。全階層を再帰取得せず、選んだ階層だけを読む。ルートではparentはnullとなる。

リモートのPython 3をSSH経由で実行し、JSON形式で一覧を受け取る。リモート側にファイルは設置しない。絶対パス・親への遡行・リンク経由でのリモートルート外へのアクセスは拒否する。

エラーは `error: {code, message}`。対象なしは404、権限不足は403、不正パスは422、SSHタイムアウトは504、接続・応答の異常は502で返す。

## 確認してから転送する

1. `POST /api/download/preview` に `{"path":"outputs/experiments/example"}` を送る。
2. 応答の `destination`（保存先）、`conflicts`（同名の既存ファイル）、`skipped`（除外対象）を確認する。ファイル一覧のパスは `initial_path` 基準。確認時には保存先を作成せず、ファイルも転送しない。
3. 衝突があれば、画面に一覧と警告を出し、ユーザーの「上書きする」の承認を得る。
4. `POST /api/download` に `{"token":"確認応答のtoken","overwrite":true}` を送る。衝突がなければ `overwrite` は省略できる。

転送は同期実行し、完了後に `status: completed` と取得元・保存先を返す。確認応答には `file_count` も含む。
確認はアプリ内で最新の1件だけ保持する。別の確認・アプリ再起動・転送開始後には以前のtokenは使えない。承認なしの上書きや、確認後の対象一覧・衝突一覧の変更は409で拒否し、再確認を求める。

`<remote_root>/outputs/experiments/example/` は `outputs/downloads/genkai/experiments/example/` に取得する。2回目の `outputs/` は付けない。
通常ファイルとディレクトリだけを転送し、シンボリックリンクや特殊ファイルは除外する。選択パスの途中にリンクがある場合と、ローカル側のファイル・ディレクトリの種別が衝突する場合は422で拒否する。

ローカルの `/usr/bin/rsync` と、リモートのrsync・Python 3が必要。SSH設定は階層取得と共用する。
確認した一覧をNUL区切りでrsyncへ渡し、チェックサムで差分を判定する。リモートや、取得元にないローカルファイルを削除しない。

失敗時は502と `transfer_failed` を返す。転送済みファイルは残るので、確認からやり直して不足分を取得する。
ディレクトリ全体を一括で切り替える保証や、転送途中のファイルのバイト位置からの再開はない。

初版は1プロセスで転送を直列に実行する。確認・転送中は取得元と保存先を他の処理で変更しないこと。
リモートの一覧確認とrsyncの読み取りは別処理であり、その間の変更を完全には防げない。
画面を閉じてもサーバー側の転送は継続し、取消API・進捗表示はまだない。
