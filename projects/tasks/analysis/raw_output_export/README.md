# ID・Group別の生出力画像

既存ビューアーの読み込み・画像対応・得票集計・軸描画を使い、保存済み結果をPNGへ出力する。学習・推論は行わない。

## 起動と設定

esn-labのルートで実行する。

```sh
uv run -m projects.tasks.cli analysis.raw_output_export
```

`cfg.yaml`で入力と対象を指定する。

- `pred_result_dir`・`judgment_result_dir`・`source_image_dir`: ビューアーと同じ保存生出力・判定CSV・明度分布画像の参照先。生出力は既存ローダー同様JSON優先、次いでNPZ。
- `groups`・`parameters`: 対象Groupとパラメータのディレクトリ名。
- `sample_ids`: 対象IDのリスト。`[]`は全件。まず少数IDで画像を確認してから全件出力できる。
- `output_dir`: 入力と重ならない専用の出力先。

他Taskと同じ初期化で設定を読み、`config.lock.yaml`を保存する。別設定は`--config`でTaskディレクトリ内のYAMLを指定する。初期化は`main()`より先に出力先を作るため、入力ディレクトリを出力先に設定しないこと。同じ出力先への再実行は同名のPNG・集計CSV・設定を上書きし、過去の別IDの画像は削除しない。別の実行を保存する場合は出力先を分ける。

## 出力

- `<parameter>/<ID>/<Group>.png`: 元画像1段＋存在するFold・train/testごとの生出力。両modeにIDがあれば別段として残す。存在しないGroup/parameterや不正な入力は停止し、その条件にないIDのパネルは作らない。
- `id_summary.csv`: parameter・ID・train/test別の評価回数、誤判定数、誤判定率。parameter・modeごとに誤判定数の降順で並ぶ。保存判定の照合不能数・不一致数も記録する。
- `config.lock.yaml`: 実行設定（通常のCLI起動時）。

PNGは明度分布画像を上段の全幅に置き、生出力は3列で左から右、上から下へFold昇順に配置する。同じFoldではtrain→test。上部にID・真値・Group・parameterと訓練／テスト別の誤判定数を表示する。採食は青、反芻はオレンジ、出力の縦軸は−1.5〜2.5。画像列の中心x＝時刻インデックスxとし、各プロットの横軸の範囲・目盛りを共通にする。全保存時刻を描画・集計し、平均化・秒換算・warmup除去はしない。同じIDの真値・系列長が条件間で違う場合は停止する。

正誤と得票率は保存生出力から再計算する。同値・同票は既存規則どおり採食。得票率は予測ラベルへの票の割合で、確信度ではない。保存判定とは別に照合し、`saved: match`・`MISMATCH`・`not_found`・`invalid_data`・`disabled`で表示する。`MISMATCH`時の得票率も再計算側の予測に対応する。元画像がない・幅が違う場合は先頭段に状態を表示し、出力値の縦軸範囲外も各段に明記する。入力・保存値は変更しない。

集計の分母は実在する評価条件の数で、独立したデータ数ではない。IDごとの評価回数が異なるため、誤判定数と率を併せて見る。失敗の多いIDは調査対象であり、ラベル誤りや入力品質の悪さを意味するものではない。

## 責務

`cfg.yaml`は参照先と対象、`app.py`は巡回と保存、`data.py`は条件別データの接続・同一性検証・ID集計、`plots.py`は図の構成を担う。設定読込・設定保存は既存のTask初期化に任せ、Webサーバー・HTTP APIは経由しない。
